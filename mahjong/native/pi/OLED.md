# OLED(小さな画面)に、麻雀先生とゲームの状態を出す

## つなぎかた(SSD1306 または SH1106、I2C)
| OLED | Raspberry Pi |
|---|---|
| GND | 物理6番 |
| VCC | 3.3V(物理1番) |
| SCL | GPIO22(物理15番) |
| SDA | GPIO23(物理16番) |

`config.txt` に(つないだピンに合わせて):
```
dtoverlay=i2c-gpio,bus=3,i2c_gpio_sda=23,i2c_gpio_scl=22
```
(`bus=` の数字は、空いている番号。 コントローラー(GPIO2・3)は i2c-1 を使うので、別の番号にする。 再起動後 `ls /dev/i2c-*` で出る)

## 入れかた
```
cd ~/Adafruit_CircuitPython_HID/mahjong && git pull
cd native/app && sh build.sh && cd ../..            # ゲーム側(状態を書き出す)を作りなおす
sudo sh native/pi/install_oled.sh
```
- ゲームなしで確かめる: `python3 native/pi/mjoled.py --demo`(場面を4秒ごとに見せる)
- 画面の絵を文字で見る(OLEDなしで): `python3 native/pi/mjoled.py --selftest`
- 大きさが 128x32 なら `MJOLED_H=32`、SH1106 なら `MJOLED_DRV=sh1106`、上下が逆なら `MJOLED_FLIP=1`(`/etc/default/mjoled` に書く)

## 仕組み
- ゲームが 0.4秒ごとに `/dev/shm/mj_oled.txt`(場面・ポーズ・フレームレートなど)を書く。 `mjoled` がそれを読んで、麻雀先生を2コマでパタパタさせ、右に数字を出す。
- 出る数字: SPD(ゲームの速さ=1コマを描く時間から出した、描ける速さ。 画面が動かない間は 前の値のまま)・DRAW(1回の平均ms)・MAX(最大ms)・KEY(ボタンを押してから画面に出るまで ms)・T(CPU温度)・FREE(まだ使える空きメモリMB。 小さいほど あぶない)・SW(使っているスワップMB。 0 が正常)・GAME(ゲーム本体のメモリMB)・P(メモリの混みぐあい%。 0に近いのが正常)・AUDIO STOP(BGMが止まっているときだけ)。
- いちばん上(16ドット、日本語)は、場面(対局・結果・クイズ…)と、「ロン!」「リーチ!」「勝ち!」「負け」などの知らせ。 日本語は Unifont の16x16で、`python3 tools/make_oled_font.py` で作る(`native/pi/oled_jp.py`)。 出す日本語は `nui.js` の `OLED-JP-BEGIN` の中。
- ゲームが止まっていると「MJ OFF」と、本体の温度・負荷・メモリを出す。
- CPUへの負担を小さくするため: 変わった所だけを送る・1秒に3コマまで・いちばん低い優先度。 I2Cはソフトウェア(GPIO)で動くので、送るあいだ だけ CPU を少し使う。 気になるときは `MJOLED_FPS=1`。
- 絵(麻雀先生18ポーズ)は `tools/ui_src/sensei_sheet.jpg` から `python3 tools/make_oled_sprites.py` で作る(`native/pi/oled_sprites.py`)。 ポーズと場面の対応は、`mjoled.py` の `POSE` と、`nui.js` の `oledState`。

## 温度と電源の見はり(常に出る)
- 画面の4行目に、いつも「T58C PWR OK」(温度と、電源の状態)が出る。 電圧が低くなると「LOW-V!」。
- **注意**(見出しが「高温」「電圧」に ときどき かわる): 温度 75C 以上 / Pi が温度や電圧で遅くなっている / 電圧が 4.63V より低い。
- **危険**(画面が白黒に ちかちか入れかわり、麻雀先生が「電源を 切って!」): 温度 82C 以上 / 電圧が低い状態が 8秒つづく(電圧計があれば 4.6V未満が 3秒)。 すぐに ゲームを止めて 電源を切り、ようすを見る。
- 温度の目安: Pi は 80C で自分で遅くなり、85C で強く遅くなる。 ヒートシンクつきで ふつうは 50〜65C。 変えるとき: `/etc/default/mjoled` に `MJ_TEMP_WARN=70` `MJ_TEMP_DANGER=80`。
- 電圧の判定は、Pi 本体の「電圧低下」の印(vcgencmd get_throttled の bit0)を読んでいる。 **Zero 2 W には 電流を測る部品がない**ので、電流(A)・実際の電圧(V)は、下の電圧電流計(INA219)をつけたときだけ出る。
- 他のプログラムのために、状態を `/dev/shm/mj_health.txt`(level=0/1/2, temp, volt, amp, thr, why)にも書く。

## 電圧・電流計(INA219 のモジュール。 つけなくても動く)
- 電源の線(5V)の途中に入れる: 電源 +5V → モジュールの VIN+ / VIN- → Pi の 5V(物理2番か4番)。 GND は つなぎなおし。
- I2C: VCC → 3.3V(物理17番) / GND → 物理9番 / SDA → GPIO2(物理3番) / SCL → GPIO3(物理5番)。 (NES コントローラーと同じ i2c-1 を 共有。 アドレスは 0x40)
- つなぐと「T58 5.1V 0.82A」と出る。 電圧 4.75V 未満・電流 2A 超で「注意」、4.6V 未満が 3秒つづくと「危険」。
- 別の番号なら `MJINA_BUS=1` `MJINA_ADDR=0x40`(`/etc/default/mjoled`)。

## 麻雀先生とずんだもん(毎回ランダム)
- 電源を入れるたびに、OLED に出る人が、ランダムで決まる: 麻雀先生(小さい顔+数字を多め) または ずんだもん(大きい顔 64×58+数字5行)。 決まったら、そのゲームが終わるまで ずっと同じ人(起動中の画面から ゲーム中まで 同じ)。
- ゲームを終えて、もう一度はじめたとき(ホームにもどらず、アプリをやりなおしたとき)に、えらびなおす。
- 固定したいとき: `/etc/default/mjoled` に `MJOLED_CHAR=sensei`(先生だけ) / `MJOLED_CHAR=zunda`(ずんだもんだけ)。 試験: `python3 native/pi/mjoled.py --demo --zunda`
- ずんだもんの絵: `tools/ui_src/zunda_pixel16.jpg`(黒髪の16表情のうち14)から `python3 tools/make_oled_zunda.py` で作る(`native/pi/oled_zunda.py`)。 場面ごとの表情は `mjoled.py` の `ZEXPR` / `ZSCENE`。
- ゲームの「設定」→「OLEDのキャラ」で、ランダム / 麻雀先生 / ずんだもん を切りかえられる(◀ ▶ か決定)。 すぐ OLED に反映され、おぼえておく(`/var/lib/mjoled_char`)ので、電源を入れた直後の画面でも同じ人が出る。 設定が「ランダム」のときだけ、電源を入れるたびに えらびなおす。 ゲームの設定が、`/etc/default/mjoled` の `MJOLED_CHAR` より優先される。

## ずんだもんペット(たまごっち風・第1段階)
- ゲームの状態ファイルに `plays`(遊んだ回数) `wins`(1位) `boots`(電源を入れた回数) `qc`(クイズ) `pt` `dan` `idle`(最後にボタンを押してからの秒) を足した。 回数は、ゲームの保存データ(成績・localStorage `mj_boots`)から。
- 表示は「OLEDのキャラ」が ずんだもん のときだけ。 ホームとタイトル・起動中に、成長の姿(たまご・ちびずんだ@5・げんきずんだ@30・おうさまずんだ@100・ひーろーずんだ@300)がぴょこぴょこ動き、右にハートの目盛り(100回で1つ、50回で半分)と、つぎの言葉までの細いバー、仲の良さ(ツン→しんゆう)、回数。 数秒おきに「なかよし・かしこさ・つよさ」の3つの目盛りに切りかわる。 3分ボタンを押さないと ねむい顔。
- 絵・見出しは `python3 tools/make_oled_pet.py` で `native/pi/oled_pet.py` を作る(元は `tools/ui_src/pet_sprites.pkl`)。 見出しは日本語を絵にして持つので、`oled_jp.py` の文字表は増やさない。
- 第2段階: のだ口調の言葉102個(1・3・5・10・15・20・25回、以降5回ごとに500回まで。 元は `tools/ui_src/pet_lines.py`)を、ホームでハートの下に流す(いまの回数までで いちばん新しい節目の言葉)。 対局のはじめ6秒は「いくのだ！」、結果・対局終了は 8秒 顔の反応のあと ハートと言葉、クイズ・勉強は ときどき 3つの目盛り。
- 第3段階: 衣装。 ホームで、ずんだもんが季節の服(お正月→春・こどもの日→夏→ハロウィン→秋→クリスマス、6つ)か職業の服(32種。 遊んだ15回ごとに ひとつ ふえる)を着る(そのままの大きさ 約45x47)。 時計がないので、電源を入れた回数で決める: おまかせ = 3回ごとに「季節」と「職業」が かわりばんこ(季節は 6つを順に、職業は 着られるものを順に)。 設定「ずんだもんの衣装」で、おまかせ / ふつうのまま / 季節だけ / 職業だけ。 起動して15秒は、着ているものの あいさつ(「〇〇に へんしん なのだ！」など)が流れる。 昇段の画面では、3秒あと、段位に合わせた職業に変身する。
- まだ: 言葉の声、診断の軸に合わせた衣装。

### ハートと3つの目盛りの意味(直した)
- ハート: 遊んだ対局の数。 100回で1つ、50回で半分。 まだ もらえていない場所は、小さな点だけ(ハートに見せない)。 50回まではハートは出ない。
- 3つの目盛り: 「あそんだ」=対局の数(500回で満タン) / 「クイズ」=答えたクイズの数(100回で満タン) / 「だんい」=いまの段位(無段〜永世名人)。
- 言葉の態度: 〜50回 ツン / 55〜145回 ツンデレ / 150〜245回 ちょいデレ / 250〜345回 なかよし / 350回〜 しんゆう。

## ずんだもんの進化(第4段階)
- 1周 = 350回。 累計の数は消さず、周のはじめの数との差で 周ごとの遊び方を見る(ゲーム側 `nui.js` の `petStep`、保存は localStorage `mj_pet2`)。
- 0〜99回: たまご・ちびずんだ・げんきずんだ。 100回めに 8つの姿(りーち・ろん・つも・なき・まもり・はかせ・たび・まるい)のどれか。 300回めに 16の最終の姿(各姿の かちぐせ=平均順位2.5位より上 / まけぐせ)。 350回めに たまごにもどり、次の周(何度でも)。
- 得点 = 割合 ÷ 目安(リーチ30% ロン50% ツモ40% なき35% ふりこみ12% 勉強0.5/局 ものしり0.3/局)。 1.25以上で いちばん高いもの、なければ まるいずんだ。 数える もの: `MJ.Stats` の play(hands/riichi/ron/win/tsumo/calls/deal)、クイズ数、勉強・診断を開いた数(`st`)、ビデオ・用語集・遊び方を開いた数(`vw`)。
- OLED へは `cp`(この周の回数) `cyc` `f1`(100回めの姿) `f2`(0=かちぐせ 1=まけぐせ) `lean`(分かれ道の前のヒント: 80回〜 / 250回〜)を送る。 ホームで 20秒周期: ふつうの画面 → 3つの目盛り → 「しんか」(姿の名前と あと何回) → 「あそぶと すがたが かわるぞ」 → ヒント。 進化・たまごにもどったときは 8秒の特別な画面。
- 姿の絵: `tools/make_oled_pet.py` の `FIRST` / `FINAL`。 衣装の職業のうち 14は、姿に使うので 衣装の一覧から外した(18に)。

## キャラの混ぜかた(設定の「OLEDのキャラ」は なくした)
- ふだん(起動・ホーム・クイズ・勉強など)は、ずんだもんの ペット。
- 対局のあいだ(対局・結果・対局終了・昇段)は、ゲームの設定「麻雀先生」が オンなら 麻雀先生、オフなら ずんだもん(ゲームが `teacher=1/0` を送る)。 `MJOLED_CHAR=sensei` で いつも先生、 `zunda` で いつもずんだもん(試験用)。
- リーチのあいだ: 自分がリーチ中は 「リーチ中」(ずんだもんは 笑顔、先生は 力が入ったポーズ)。 相手がリーチしているあいだは「警戒!」。 リーチ宣言の瞬間も 同じ 力の入ったポーズ。
- 勉強の階層(勉強・学習・用語集・遊び方・診断)は、いつも麻雀先生。 クイズは ずんだもんのまま、答えを見たとき 正解=喜ぶ(笑顔・「正解!」) / おしい=心配顔 / ちがう=あせあせ顔、終わりの画面で 6割以上正解なら 喜ぶ。

## クイズの級(OLED)
- ゲームが `ql`(0=はじめ / 1〜10=10級〜1級 / 11=師範)と `qs`(師範の星)を送る。 「あそんだ・クイズ・だんい」の目盛りの「クイズ」の行に、級を出す。 級が上がる画面では「昇級!」。

## 電源を入れてすぐ OLED を出す(起動を速く)
- 起動して 60秒までは ふつうの優先度で動き(以前は 最初から いちばん低い優先度で、起動の負荷が高いあいだ 後回しになっていた)、そのあと 低い優先度にする。
- 最初の画面(「起動中」)を出してから、ペットの絵(約200KB)を読む。 先にコンパイル(.pyc)しておく(`install_oled.sh`)。 i2c の装置が見つかるまでの再試行は 0.3秒おき。
- OLED が出るのは、Linux が起きたあと(電源を入れてから 10秒ほど後)。 それより前は、電源LEDだけ(ハードウェア)。 さらに速くしたいときは、`systemd-analyze blame` を見て、使わないサービスを止める。

### 起動の時間(実測: 2026-11 の Zero 2 W)
- `systemd-analyze`: カーネル 5.5秒 + ユーザー空間 9.3秒 = 14.7秒。 OLED のサービスは ユーザー空間の いちばん はじめ(sysinit)に動くので、OLED が出るのは 電源を入れて 6〜8秒ごろの見こみ(未測定)。
- ユーザー空間で 時間がかかっているのは、自動更新(4.6秒)・ファイル点検(2.8秒)・ネット接続の待ち(2.3秒)・モデム(1.3秒)など。 ゲームの起動を速くしたいとき `sudo native/pi/boot_slim.sh on`(元に戻すのは `off`)。 OLED の出る時刻は ほとんど変わらない。 カーネル側(5.5秒)を縮めるには config.txt の `disable_splash=1` `boot_delay=0` など。

### 画面の乱れ(横すじ・かすれ)が出たとき
- 原因の見こみ: OLED の I2C は、ソフトで動かす方式(i2c-gpio)なので、CPU が忙しいとき(ゲーム中)に、送りまちがいが起きることがある。 以前は「変わった所だけ」送っていたので、まちがって送られた所が、そのページが変わるまで残った。
- 対策(済): 1コマごとに 1ページずつ、全部を送りなおす(約 8コマで 全体が直る)。 20秒ごとに、表示の設定(明るさなど)も送りなおす。
- それでも出るとき: config.txt の `dtoverlay=i2c-gpio,...` の行の最後に `,i2c_gpio_delay_us=5` を足す(通信をゆっくりにして、乱れにくくする)。 配線が長い・ゆるいときも乱れる(GND と 3.3V の線をしっかり)。

### 画面の点検
- `sudo systemctl stop mjoled` のあと、`python3 mjoled.py --fill`(全部を白)や `--grid`(格子)を 20秒 出す。 上の 16〜20ドットだけ すじが入るなら、画面そのもの(黄色と青の 2色の画面の 上の黄色の帯)の見えかたの可能性。 全体が きれいなら、送りまちがいで、1コマずつの送りなおしで 直る。

### すじが消えないとき(画面の故障を疑う前に)
- 試す順: ①`--fill` / `--grid` で全面を見る ②ケースの穴・押さえで、画面のふち(特に ケーブルのある辺)を 押していないか。 外して 見る ③`/etc/default/mjoled` に `MJOLED_CONTRAST=0x7F`(明るさを下げる)、`MJOLED_CLK=0xF0`、`MJOLED_PRECH=0x22` を 1つずつ足して `sudo systemctl restart mjoled` ④config.txt の i2c-gpio に `,i2c_gpio_delay_us=5` ⑤別の OLED(0.96インチ SSD1306、数百円)に交換。

## 上の16ドットを使わない配置(すじが入る画面のため)
- 画面の上の 16ドット(2ページぶん)には何も描かず、下の 48ドットだけを使う(`MJOLED_TOP=16` が標準。 `0` にすると上まで使う)。 全部の画面を 48ドットの高さで組みなおした: 麻雀先生の絵(40x48)はそのまま、ずんだもんの顔と姿は 1.5倍(48x42)、衣装の絵(45x47)はそのまま。 右の文字は 16ドットの行が 3つ(または 見出し+5x7の数字の行が 3つ)。
- 警告の白黒反転も、上の使わない帯は そのまま(反転しない)。
- 上の 16ドットには、ニューヨークの夜景を 白黒反転で出す: 空は 点の細かさで(上は まばら、下ほど明るい)、ビルは 黒いシルエット、窓だけ 白く小さく光る(3秒ごとに少し入れかわる)。 月は 白い丸、塔の先の灯りが 1秒ごとに点滅。 空は細かい点なので、横線が入っても 質感に見えて 目立たない。 いらないときは `/etc/default/mjoled` に `MJOLED_DECOR=0`。
